# 工作流与状态机

## 1. 状态

| 状态 | 进入条件 | 主要产物 | 离开条件 |
|---|---|---|---|
| `INTAKE` | 只有目标或 Prompt | `intake.md` | 输入合同清楚 |
| `DATA_REQUIRED` | 无真实商家测试数据 | 数据模板、缺口清单 | 用户补齐数据 |
| `ASSEMBLE` | 有数据，Prompt 未冻结 | 分发矩阵、展开后的 Prompt | 静态审查通过 |
| `INPUT_GATE_FAILED` | 多模态/字段/URI 不合格 | 校验报告 | 修复后复验 |
| `READY_TO_SUBMIT` | 两次数据校验均通过 | 冻结配置 | 用户授权正式批测 |
| `WAITING` | 已获得 experiment_id | status 文件、hook | 终态出现 |
| `RUN_FAILED` | 实验失败/终止 | 失败清单 | 选择重试或修复 |
| `ANALYZE` | 实验终态且有结果 | manifest、总览、对比图 | 四维评审完成 |
| `OPTIMIZE` | 结论未通过 | diagnosis、vNext、diff | 用户批准重跑或结束 |
| `PASS` | 所有硬门槛通过 | 最终报告、稳定 Prompt | 结束 |

## 2. Intake 最小输入

- 当前完整 Prompt 或 Prompt ID + 版本。
- 目标图片模型、画幅和数量。
- 60 条商家样本，或数据来源位置。
- 商家字段含义：门店名、商品名、品类、必显文案、可选文案、禁用文案。
- 稳定图片 URI；正式运行前生成的新鲜 URL 只是运行态字段。
- 用户对重跑成本的授权范围：仅一轮、最多 N 轮、或只产出 vNext 不重跑。

## 3. 60 条的推荐分层

不要简单随机抽 60 条。覆盖：

- 高频类目与长尾类目。
- 中文短标题、长标题、中英混排、数字/符号。
- 单图与双图。
- 主体形状、明暗、背景复杂度和裁切差异。
- 品牌/门店名相近、容易混淆的样本。
- 6 个分发布局策略各约 10 条，且类目尽量均衡。

如数据不足 60 条，明确“样本不足”并降低结论置信度，不通过复制同一商家凑数。

## 4. 两级实验

### 4.1 分发干跑

不生图或只做少量冒烟验证，检查 60 条是否都有可解释的分发变量、商家事实是否原样进入、图片变量是否为多模态、可见文字白名单是否有限、占位符是否已展开。

### 4.2 正式 60 图

只有干跑通过才提交。提交时冻结 eval-set、Prompt、模型、字段映射、生成配置和分发策略版本。

## 5. 等待策略

默认退出 agent 回合，让 `watch_experiment.py` 工作。状态脚本输出：

- `latest_status.json`：最新快照。
- `status_history.jsonl`：仅记录状态或计数变化。
- `final_status.json`：终态快照。
- `EXPERIMENT_DONE` 或 `EXPERIMENT_FAILED`：零字节标记文件。

用户回来后直接从这些文件恢复，不重复查询历史状态。

## 6. 失败分叉

### 数据/链路失败

图片引用为空、URL 过期、映射错位或结果与输入无法关联时，停止视觉归因，先修 URI 刷新和字段映射。不要通过增加 Prompt 约束掩盖输入缺失。

### 运行失败

部分行生成失败但输入合格时，优先 `retry_failure`。只有配置整体错误才新建实验，避免重复付费生成成功行。

### 质量失败

链路有效但四维门槛未通过时，产出 vNext 和最小重测计划。未经用户授权不自动提交第二轮 60 图。

## 7. 迭代停止条件

满足任一即停止：

- 四维硬门槛全部通过。
- 达到用户授权轮数/预算。
- 两轮之间核心指标改善不足 5 个百分点。
- 商家引用或文字准确率发生关键回退。
- 新问题的严重度高于被修复问题。
