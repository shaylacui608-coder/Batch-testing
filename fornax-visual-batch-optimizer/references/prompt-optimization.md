# 由评审结论反推 Prompt

## 1. 先归因层级

按顺序定位：输入链路 → 数据 → 字段映射 → 单条样本 → 分发器/Variant → 公共 Prompt → 模型随机性。不要用公共 Prompt 修复输入链路问题，也不要因单条异常重写整个 Prompt。

## 2. 证据到修改的映射

| 结论 | 优先修改 | 避免 |
|---|---|---|
| 差异化低 | 明确 4–6 个互斥构图策略及配额；位置、尺度、留白、配色设为可追踪变量 | 只加 “more diverse” |
| 美观不足 | 固定层级、主体占比、接触阴影、装饰上限和留白规则 | 继续堆装饰形容词 |
| 乱码高 | 收紧可见文字白名单；删除非必要小字；不确定时用图形占位 | 要求更多英文氛围字 |
| 商家引用错 | 强化事实优先级和 exact copy；禁止推断；确认多模态链路 | 让风格模板提供通用品牌词 |
| 商品保真差 | 参考图作为身份事实源，限制新增主体/镜像/品类替换 | 只写“参考图片”但不传图片 |

## 3. 修改记录

每条写明 Evidence、Root cause、Change、Expected effect、Risk、Validation。

## 4. 最小变更原则

- 保留已通过的设计系统和稳定约束。
- 每轮最多处理 1–2 个高优先级问题族。
- 将“删除”与“新增”同等看待，过长 Prompt 会增加冲突。
- 指令要可观测，例如“辅助文字最多 2 组”，不要只写“不要太多”。
- 对互斥分支写清条件，不让模型同时执行。

## 5. 复测策略

先用失败样本和边界样本做 12–20 图定向复测；没有关键回退后，再申请第二轮 60 图正式验证。严格 A/B 时保持数据、模型和分发配额不变，只替换 Prompt 版本。

## 6. 停止与回滚

商家准确率或主标题准确率下降时立即回滚。两轮改善少于 5 个百分点时停止堆指令，重新检查模型能力或数据设计。未获重跑授权时，只交付 vNext、diff 和复测计划。
